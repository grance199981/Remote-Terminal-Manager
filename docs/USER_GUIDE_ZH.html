Remote Terminal Manager · 使用说明

基于 Tailscale 的 SSH / SFTP / Ubuntu 远程桌面管理工具

本文档说明如何让 Windows 本机和 Ubuntu 服务器进入同一个 Tailscale VPN 网络，如何准备服务器依赖，以及如何使用 Remote Terminal Manager 连接终端、传输文件和打开远程桌面。

1. 软件能力概览

SSH 终端通过密码或私钥连接授权服务器，支持多标签终端。
SFTP 文件传输浏览本地和远程目录，支持上传、下载、新建目录和删除远程项。
Ubuntu GUI 远程桌面通过 Tailscale IP + SSH + VNC/noVNC 在软件内打开图形界面。

推荐使用方式是：所有设备接入同一个 Tailscale Tailnet，然后软件通过 Tailscale IP 访问服务器的 SSH、SFTP 和 noVNC 服务。

2. 配置 Tailscale VPN

Tailscale 会给每台设备分配一个 100.x.y.z 的私有 VPN IP。只要本机和服务器登录同一个 Tailscale 账号或同一个 Tailnet，就可以在校外像校内一样 SSH 到服务器。

2.1 注册和登录

  1. 访问 tailscale.com 注册账号。
  2. 在 Windows 本机安装 Tailscale 客户端并登录。
  3. 在 Ubuntu 服务器安装 Tailscale 并登录同一个账号或同一个 Tailnet。

2.2 Windows 本机检查

打开 PowerShell，检查服务器 SSH 端口是否可达：

Test-NetConnection 服务器的TailscaleIP -Port 22

如果显示 TcpTestSucceeded : True，说明网络层已经打通。

2.3 Ubuntu 服务器安装 Tailscale

如果有 sudo 权限，可使用官方安装脚本：

curl -fsSL https://tailscale.com/install.sh | sh
sudo tailscale up

如果当前用户没有 sudo 权限，需要让服务器管理员安装并登录授权。

查看服务器 Tailscale IP：

tailscale status
tailscale ip -4
示例：如果服务器 Tailscale IP 是 100.106.48.42，软件中 Host 就填写 100.106.48.42，端口填写 22。

3. Ubuntu 服务器准备

3.1 SSH 服务

服务器必须开启 SSH 服务：

sudo apt update
sudo apt install -y openssh-server
sudo systemctl enable --now ssh
sudo systemctl status ssh

本机测试：

ssh 用户名@服务器TailscaleIP

3.2 远程桌面依赖

如果要使用 Ubuntu GUI 远程桌面，需要安装 XFCE、TigerVNC、noVNC 和 websockify：

sudo apt update
sudo apt install -y \
  xfce4 xfce4-goodies \
  tigervnc-standalone-server tigervnc-common \
  novnc websockify \
  dbus-x11 xterm iproute2
注意：如果你的普通账号没有 sudo 权限，请让服务器管理员执行上述命令。软件里的“安装依赖并启动”按钮也需要 sudo 权限；没有 sudo 时不要使用这个按钮。

3.3 VNC 密码

软件会在通过 SSH 启动远程桌面时尝试创建 ~/.vnc/passwd。如果失败，可以在服务器上手动设置：

vncpasswd

4. 启动软件

当前 Windows 便携版 exe 位于：

D:\Doctor\remote control\apps\desktop\release\Remote-Terminal-Manager-0.1.0-portable-x64-native-scale.exe

双击即可运行，不需要安装。

5. 添加服务器设备

点击左侧“新增”。
填写设备名称，例如 server2。
Host 填写服务器的 Tailscale IP，例如 100.106.48.42。
端口通常填写 22。
用户名填写 Ubuntu 登录用户。
认证方式选择密码登录或私钥登录。
保存后，设备会出现在左侧列表。

6. SSH / 本机终端

按钮作用
连接 SSH连接左侧选中的服务器，打开远程 shell。
PowerShell打开本机 Windows PowerShell。
CMD打开本机 Windows CMD。

终端支持多标签页。输入密码时终端通常不显示字符，这是 Linux/SSH 的正常行为。

7. 文件传输

  1. 左侧是本地目录，右侧是远程目录。
  2. 可以手动输入路径，例如 D:\Doctor\OverLock_SNN\code 或 /home/ghr/OverLock_SNN。
  3. 选择本地文件或文件夹后点击“上传所选”。
  4. 选择远程文件或文件夹后点击“下载所选”。
  5. 可在远程目录中新建文件夹或删除远程项。
大文件或大目录传输建议先压缩成 .zip、.7z 或 .tar.gz 后再上传，速度和稳定性会更好。

8. 远程桌面

远程桌面基于 XFCE + TigerVNC + noVNC/websockify。软件会通过 SSH 在服务器上启动 VNC/noVNC，然后通过 Tailscale IP 或 SSH 隧道打开页面。

确认服务器已安装第 3.2 节中的依赖。
在软件里选择设备，打开“远程桌面”。
输入 SSH 密码。
分辨率建议先选择 1280x720；如果流畅再提高。
点击“连接/重连”。
等待软件显示“已连接远程桌面”。

分辨率与流畅度建议

场景推荐设置
普通 SSH 辅助操作1280x720，色深 16 或 24
轻量图形界面操作1600x900，色深 24
高分辨率显示1920x1080，但可能更卡

如果点击位置错位，通常是旧版页面或浏览器缓存导致。请关闭旧 APP，使用最新版 exe，并点击“连接/重连”重新生成服务器上的 remote.html。

如果远程桌面里打开了太多 ToDesk 或其他窗口，可以在 SSH 终端中执行：

ps aux | grep -i todesk
pkill -f ToDesk

9. 给 Codex/Agent 使用

如果经常让 Codex 或其他 Agent 在服务器上跑实验，建议统一使用 Tailscale IP + SSH。当前可用的本机 skill 路径为：

C:\Users\zijia\.codex\skills\remote-ssh-experiment

给 Agent 的典型指令可以写成：

使用 remote-ssh-experiment skill，通过 Tailscale IP 连接 server2，在 /home/ghr/项目目录 下同步代码、启动实验并监控日志。

建议所有远程实验都明确服务器名称、Tailscale IP、远程工作目录、Python/Conda 环境路径、GPU 编号、日志位置以及是否允许长时间运行。

10. 常见问题

10.1 SSH 连不上

Test-NetConnection 服务器TailscaleIP -Port 22
ssh 用户名@服务器TailscaleIP
  • 确认本机和服务器 Tailscale 都是 Connected。
  • 确认服务器 SSH 服务已启动。
  • 确认 Tailscale ACL 没有禁止访问。

10.2 noVNC 端口拒绝连接

ss -ltnp | grep 6080
ss -ltnp | grep 5901

如果没有监听，重新在软件里点击“连接/重连”。如果缺包，让管理员安装第 3.2 节的依赖。

10.3 画面卡顿

  • 降低分辨率到 1280x720。
  • 降低色深到 16。
  • 关闭远程桌面中不必要的软件，例如 ToDesk。
  • 尽量用 SSH 终端完成实验操作，GUI 只用于必要的图形界面。

10.4 文件名显示 invalid encoding

这是远程 Linux 目录里存在非法 UTF-8 文件名。可以用 Python 检测：

python3 - <<'PY'
import os, json
root = os.path.expanduser('~').encode()
rows = []
with os.scandir(root) as it:
    for e in it:
        try:
            e.name.decode('utf-8')
        except UnicodeDecodeError:
            rows.append({'hex': e.name.hex(), 'is_dir': e.is_dir(follow_symlinks=False)})
print(json.dumps(rows, indent=2))
PY

11. 安全建议

  • 只连接自己拥有或已获授权的服务器。
  • 不要把 SSH 密码写进公开文档、代码仓库或截图。
  • 优先使用 Tailscale IP，避免把 SSH、VNC 或 noVNC 直接暴露到公网。
  • 如果多人共享服务器，建议使用独立账号和独立 VNC 密码。
  • 远程桌面使用完后，可以关闭不需要的 GUI 程序以减少资源占用。
